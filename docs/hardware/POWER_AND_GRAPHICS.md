# Orange Pi Zero 2W: питание и проверка нового образа

## DFR0528

DFRobot DFR0528 содержит MAX17043 и собственный MCU. Хост использует MCU по
адресу `0x10`; это не прямой доступ к регистрам MAX17043. Протокол описан в
[справочнике DFRobot](https://wiki.dfrobot.com/dfr0528/docs/19883).
В BatteryMonitor проверяются PID `0xDF` и версия прошивки. SOC вычисляется
точно как двоичная доля; неуспешное чтение не считается свежим измерением.

Номер `hardware.battery.i2c_bus` нужно сопоставить с реальными SDA/SCL и Linux
адаптером. На проверенной старой SD `/dev/i2c-3` отсутствовал, а внутреннее
устройство AC200 имело тот же адрес `0x10` на другом адаптере. Не менять адрес
датчика и не опрашивать случайный адаптер только из-за совпадения адреса.

Плата имеет выход 5 V, максимум 2 A по [спецификации DFRobot](https://wiki.dfrobot.com/dfr0528).
Нужно измерить общий ток Orange Pi, модема и подключённых модулей под нагрузкой.
Программное ограничение частоты CPU не задаёт ток зарядки UPS. Порог аппаратного
отключения зависит от прошивки UPS: в V1.0 это 10%, в V1.1 — 5%. Автоматическое
завершение работы в этом изменении не включено; его порог нужно выбирать с
запасом относительно подтверждённой прошивки и реального времени shutdown.

## Управление CPU в приложении

Settings показывает CPUFreq policies, текущий governor, частоту и пределы.
Можно выбрать governor из списка ядра и максимальную частоту из таблицы ядра.
Изменения выполняются только по нажатию кнопки, применяются к выбранной policy
и проверяются чтением обратно. Они не записываются в загрузочные настройки,
не меняют напряжения и не отключают тепловую защиту. После перезагрузки или
действия другого менеджера питания настройки могут измениться.

Для записи нужны предусмотренные ОС права на CPUFreq sysfs; приложение не
повышает привилегии автоматически. При отсутствии CPUFreq или доступа выводится
причина. Governor `userspace` не предлагается в UI, поскольку требует отдельного
управления целевой частотой. Если таблица частот не предоставляется ядром, UI
показывает governors без выдуманных частот.

Реализация использует [штатный интерфейс Linux CPUFreq](https://cdn.kernel.org/doc/html/latest/admin-guide/pm/cpufreq.html).
Это также проверочный прототип для дальнейшего развития форка официального
`armbian/configng`, выбранного основным системным конфигуратором.

## GPU, экран и видео проверяются отдельно

На старой карте (`6.12.47-current-sunxi64`) найден Panfrost и Mesa 22.3.6,
но GPU отключён в проверенном DT. Overlay `gpu` есть на диске, но указан
только в домашней копии armbianEnv, которую загрузчик не читает.
В сохранённом журнале Cedrus зарегистрировал `/dev/video0`. Это не тест
конкретного кодека, файла или приложения.

Современная [Mesa Panfrost](https://docs.mesa3d.org/drivers/panfrost.html)
поддерживает Mali-G31. Возможности конкретного образа определяют установленные
версии ядра, Mesa и приложение. Поддержка Vulkan в актуальной документации Mesa
не означает её наличие в Mesa 22.3.6 или работоспособность выбранной игры.
GPU-рендеринг, вывод HDMI и декодирование VPU имеют разные драйверы.

На странице [Armbian для Zero 2W](https://armbian.com/boards/orangepizero2w)
на 26 октября 2026 года доступны community rolling образы с ядром 6.18.57:
Debian 13 Minimal, Ubuntu 26.04 Minimal и Xfce. Образ пока не выбран. Для
своего приложения разумный первый кандидат — Debian Minimal, для проверки
готового рабочего стола — Xfce; выбор не заменяет испытания оборудования.
Старый Armbian может содержать патчи, отсутствующие в другом ядре: например,
в [upstream Cedrus Linux 6.18](https://github.com/torvalds/linux/blob/v6.18/drivers/staging/media/sunxi/cedrus/cedrus.c)
нет matching entry для `allwinner,sun50i-h616-video-engine`. Версия ядра сама
по себе не доказывает сохранение VPU-поддержки из старого Armbian.

Проверять новый образ удобно на второй SD, сохранив исходную карту для возврата.
Сначала загрузить стандартную конфигурацию, затем переносить по одному overlay,
проверяя его наложение на новый DTB. Не копировать старый `rootdev=UUID=...`.

На работающей плате собрать:

```sh
uname -r
cat /sys/devices/system/cpu/cpufreq/policy*/scaling_driver
cat /sys/devices/system/cpu/cpufreq/policy*/scaling_available_governors
cat /sys/devices/system/cpu/cpufreq/policy*/scaling_available_frequencies
i2cdetect -l
ls -l /dev/dri /dev/video* /dev/spidev* /dev/i2c-*
glxinfo -B
eglinfo -B
vulkaninfo --summary
v4l2-ctl --list-devices
ffmpeg -hwaccels
```

Некоторые утилиты потребуют установки; glxinfo требует работающую X-сессию,
eglinfo проверяет доступные EGL-платформы. Список `ffmpeg -hwaccels` показывает
возможности сборки, а не успешное аппаратное декодирование. Подтверждение:
реальный renderer вместо llvmpipe, журнал выбранного плеера с конкретным
аппаратным декодером, затем воспроизведение тестовых H.264/H.265 файлов и
оценка пропущенных кадров/CPU. Наличие `/dev/video0` само по себе недостаточно.
Игры проверять по одной, начиная с native ARM64/OpenGL ES, с измерением
температуры, FPS и питания; x86-эмуляция является отдельной задачей.
